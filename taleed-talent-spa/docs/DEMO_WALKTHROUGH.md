# Demonstration guide

## Before the client session

Install the resolved dependency graph, run the full checks, review all browser tests and fix failures. Start Vite or serve a successfully built `dist/` over localhost/HTTPS. Do not begin the session by upgrading packages. Use a separate browser profile with no real records.

Start with this sentence:

> “This is an interactive prototype of the Talent & Team Development journey. It uses fictional data saved in this browser. Account verification, permissions and sharing audiences are simulated; the production service will use the approved Taleed backend.”

The source copy and visual tokens remain provisional. Do not present the sample activities as a verified transcription or the typography as the official licensed Taleed product font.

## Journey 1: See the value immediately

Open the default Amina Hassan persona at Overview. Explain the next useful action, the selected monthly theme, completed occurrences and delivered scope coverage. Open “Continue my monthly plan” to see the three pinned activity commitments and their individual occurrences.

The plan has three starter commitments; it is not automatically complete because those cards were selected. A completed recurring occurrence does not complete every repeat. The cancellation denominator rule is visible in the metrics.

## Journey 2: Build a balanced plan

Open My monthly plan or Build a plan. Choose **October 2026** to avoid duplicating the seeded September plan. Keep Develop as the focus, name the plan, and continue. Attempt to continue with no selections to demonstrate validation.

Select exactly one individual, one culture and one team activity. Select a different card in an occupied scope to demonstrate the replacement confirmation. Continue to schedule: choose one-off development events or daily/weekly recurrence with valid October dates. Review the plan and activate it.

Wait for the actual local-save indicator before refreshing. The plan should survive refresh. Repeated seed booting must not overwrite it. Failure here blocks demo acceptance.

## Journey 3: Follow through without pretending everything is done

Open Calendar. Switch between month and agenda. Change an occurrence to In progress, Blocked, Completed or Cancelled and save. Observe the changed eligible denominator and coverage only when actual work is completed.

Open the plan and reschedule a future commitment. Completed/cancelled and past records should remain unchanged. Add a custom development commitment with declared scope; it is your private authored activity, not a globally approved library item.

Close the month while some work remains incomplete. Provide an honest explanation and optional private reflection. Open history to view the immutable snapshot. Reopen for a correction, make a change, and close again: the prior revision must remain available.

## Journey 4: Private development conversation

Open Conversations, create a record, and use a fictional colleague alias only. Review the six-step illustrative guide, three note areas and seven follow-ups. Add a goal, next action and follow-up date. Complete and preview the personal report.

Switch to Omar Nasser or the Champion persona. The other person’s conversation must not appear. Direct navigation to its saved ID should show the personal-record exception state. This demonstrates UI boundaries only, not real browser data security.

## Journey 5: Optional numeric well-being reflection

Open My well-being. Explain that the feature is optional and not a company assessment. Acknowledge the demo privacy notice. Start a blank reflection; no scores should be preselected.

Enter eight ratings and confirm that no total is shown. Add the ninth. Use the dimension order in the interface and the example **8, 7, 8, 3, 6, 3, 6, 8, 5** to obtain **54 / 90**. Do not attach a classification or medical conclusion.

Choose a focus dimension and write three personal actions. Complete, open the report and then create a correction revision. The profile should never appear on a Champion or Taleed dashboard, including as a participation count.

## Journey 6: Champion sharing → Taleed view

Switch to **Noor Saleh**, choose **August 2026** in the header, and open Summary & sharing. This seeded record has **five scheduled occurrences, one cancelled, two completed from four eligible, 50% follow-through and two of three scopes delivered**.

Open Preview & share. Show the exact JSON field list. There are no leader names, aliases, private notes, custom activity titles, conversation records or well-being fields. Tick the explicit confirmation and share in the browser demo.

Switch to **Mariam Ahmed** and open Shared portfolio. The same effective summary should be visible for the assigned Cedar Works cohort. Review the exact filter/row preview before CSV export. Do not describe not-shared companies as zero performers.

Return to the Champion, share a replacement revision, and verify that the analyst counts one effective summary. Withdraw it and confirm it disappears from the effective portfolio. Explain that downloaded copies cannot be recalled.

## Journey 7: Membership and source governance

As Noor, invite a fictional leader using an `example.test` address. No email is sent. Test acceptance using the exact invited address; also demonstrate expired, revoked and already-used states. There is no automatic organization access based on domain matching.

As **Hassan Abdullah**, open Content workspace. Show seven source metadata records and their dependencies. Create a draft activity revision, compare it with its predecessor and attempt publication while the source is unresolved; this must be blocked. For a clearly labeled simulation, resolve the dependency and record demo approval, then publish. Old plan content must not change.

## Journey 8: Saving and recovery

Open Settings. Enable simulated save failure; change a preference. The save indicator must not say Saved. Disable failure and retry. Test a real second browser tab separately: a clean tab can receive updates, while a dirty stale tab must show a conflict rather than silently overwrite.

Switch to the administrator and export both in-memory backup and original stored bytes. Explain that this development console contains all fictional personas and is not a production permission. Import a valid backup only after preview/confirmation. Try a corrupted/unknown-version file: it must not replace stored data. Reset only when intentionally discarding the whole demo.

## Finish with a decision, not a production claim

Ask the client to validate the journey, terminology, required information, sharing boundary and content ownership. Record design/source/privacy decisions separately from acceptance of this prototype’s functions. Real authentication, protected persistence, source files, company isolation and operations require the next implementation phase.
